## 🔑 1. ระบบจัดการผู้ใช้และยืนยันตัวตน (Authentication & Auth Flow)
ระบบนี้ดูแลการสมัครสมาชิก, การเข้าสู่ระบบ (ทั้งแบบธรรมดาและ Google), และการเปลี่ยนรหัสผ่าน

### 🌐 สิ่งที่ต้องทดสอบบนหน้าเว็บ UI (Web UI Testing)
* [ ] **สมัครสมาชิก (Register Page - `/register`):** 
  * ทดสอบกรอกข้อมูลถูกต้อง -> ระบบแสดงการส่งอีเมลยืนยันสำเร็จ
  * ทดสอบกรอกข้อมูลไม่ถูกต้อง (เช่น รหัสผ่านสั้นเกินไป, อีเมลซ้ำ) -> ระบบต้องแจ้งเตือนความผิดพลาด
* [ ] **เข้าสู่ระบบปกติ (Login Page - `/login`):**
  * ทดสอบใช้ Username/Password ที่ถูกต้อง -> เข้าสู่ระบบสำเร็จและนำทางไปยังหน้าแรก
  * ทดสอบใช้รหัสผ่านผิด -> แสดงข้อความแจ้งเตือน Error
* [ ] **เข้าสู่ระบบด้วย Google (Google Login OAuth):**
  * ทดสอบคลิกปุ่ม "Sign in with Google" -> แสดงป๊อปอัพเข้าสู่ระบบของ Google
* [ ] **ลืมรหัสผ่าน (Forgot Password - `/forgot-password`):**
  * ทดสอบกรอกอีเมลเพื่อส่ง Link รีเซ็ตรหัสผ่าน
* [ ] **ตั้งค่ารหัสผ่านใหม่ (Reset Password - `/reset-password`):**
  * ทดสอบการยืนยันรหัสผ่านใหม่หลังคลิกลิงก์จากอีเมล

### ⚡ สิ่งที่ต้องทดสอบบนหลังบ้าน (Backend API Testing)

* [ ] **POST** `/api/users/google-login/` (ส่ง Google Token แลกกับ JWT Token)
* [ ] **GET** `/api/users/verify-email/` (ทดสอบการส่ง Token เพื่อยืนยันอีเมล)

## 🛡️ 7. ระบบป้องกันและตรวจสอบความยาวข้อมูลอินพุต (Input Length & Character Constraints Validation)
การทดสอบเพื่อรับประกันความปลอดภัยของระบบและการแสดงผลข้อผิดพลาดเมื่อผู้ใช้งานป้อนตัวอักษรที่มีความยาวเกินโควตาที่ฐานข้อมูลหรือระบบกำหนดไว้ (Boundary Value & Input Validation Testing)

### 🌐 สิ่งที่ต้องทดสอบบนหน้าเว็บ UI (Web UI Testing)
* [ ] **การควบคุมความยาวที่ระดับฟอร์ม (Front-end HTML5 Validation):**
  * ตรวจสอบฟอร์มกรอกข้อมูลต่างๆ ว่ามีแอตทริบิวต์ `maxlength` ป้องกันผู้ใช้พิมพ์เกินความยาวสูงสุดหรือไม่ (เช่น Username ห้ามเกิน 150 ตัวอักษร, เบอร์โทรศัพท์ห้ามเกิน 20 ตัวอักษร)
  * หากกรอกเกินผ่านการ Copy/Paste -> ระบบหน้าบ้านต้องตัดตัวอักษรส่วนเกินออกทันที หรือแสดงกล่องข้อความเตือนความผิดพลาดสีแดงชัดเจน (Validation Error Message)

### ⚡ สิ่งที่ต้องทดสอบบนหลังบ้าน (Backend API Testing)
ทดสอบส่งข้อมูลที่มีความยาวเกินกว่าขีดจำกัดสูงสุดของฐานข้อมูลผ่าน API (Boundary Testing) เพื่อตรวจดูว่าระบบหลังบ้านตอบกลับโค้ด `400 Bad Request` พร้อมข้อความแจ้งความผิดพลาดที่เหมาะสม และไม่เกิดระบบล่ม (Server 500 error):
* [ ] **ทดสอบความยาวชื่อผู้ใช้งาน (Username Validation):**
  * ส่งข้อมูลสมัครสมาชิกที่มี `username` ยาวเกิน 150 ตัวอักษร (เช่น 151 ตัวอักษร) -> คาดหวังได้รับการตอบกลับโค้ด `400` พร้อมข้อความเตือนเกี่ยวกับข้อจำกัดจำนวนตัวอักษร
* [ ] **ทดสอบความยาวเบอร์โทรศัพท์ (Phone Validation):**
  * อัปเดตโปรไฟล์ด้วยเบอร์โทรยาวเกิน 20 ตัวอักษร -> คาดหวังการตอบกลับโค้ด `400` แจ้งเตือนเรื่องความยาวเบอร์โทร
* [ ] **การสร้างบทความบล็อก (Blog Article Validation):**
  * ตรวจสอบฟอร์มสร้างบทความบล็อก `/blog/create` เมื่อกรอกหัวข้อบทความ (Title) ยาวเกิน 255 ตัวอักษร -> ระบบแสดงตัวนับตัวอักษรแบบเรียลไทม์เป็นสีแดงเตือน (เช่น `256/255`) และแสดงข้อความแจ้งเตือนการป้อนข้อมูลเกินขีดจำกัด
  * ตรวจสอบการส่งข้อมูล Title สั้นกว่า 5 ตัวอักษร หรือ Content สั้นกว่า 10 ตัวอักษร -> ระบบหน้าบ้านสกัดกั้นการส่งข้อมูล และแสดง Toast แจ้งเตือนข้อผิดพลาดทันที
  * ตรวจสอบความยาวของชื่อและ Slug ที่ระดับหลังบ้าน (Backend Validation & Truncation) -> ส่งบทความที่มีหัวข้อยาวมากๆ -> หลังบ้านตอบกลับ `400 Bad Request` หากมีความยาวผิดกฎ หรือย่อทอน (Truncate) ค่า `slug` ให้อยู่ภายใต้โควตา 255 ตัวอักษรโดยไม่เกิด Server 500 error ล่มในระบบฐานข้อมูล PostgreSQL

### 📋 8. ตารางนโยบายขีดจำกัดตัวอักษรของระบบ (System-wide Input Length Constraints Policy)

นี่คือข้อกำหนดนโยบายความยาวของข้อมูลและจำนวนตัวอักษรของระบบทั้งหมดเพื่อป้องกันข้อผิดพลาดของฐานข้อมูล:

| ฟิลด์ข้อมูล (Input Field) | ขีดจำกัด DB (Database Limit) | นโยบายความยาวที่แนะนำ (Constraint Policy) | การตรวจเช็คและการตอบสนอง (Validation Strategy) |
| :--- | :--- | :--- | :--- |
| **ชื่อผู้ใช้ (Username)** | `max_length=150` | 3 - 150 ตัวอักษร | Frontend (maxlength) & Backend Validation |
| **อีเมล (Email)** | `max_length=254` | สูงสุด 254 ตัวอักษร | รูปแบบ Email Regex & Backend Model |
| **รหัสผ่าน (Password)** | ไม่มีขีดจำกัดตรงๆ | 8 - 128 ตัวอักษร | Frontend Min Length 8 |
| **เบอร์โทรศัพท์ (Phone)** | `max_length=20` | 9 - 20 ตัวอักษร | Frontend (maxlength=20) & DB Check |
| **เลขหนังสือเดินทาง (Passport No.)** | `max_length=50` | 5 - 50 ตัวอักษร | Frontend (maxlength=50) & DB Check |
| **ที่อยู่ปัจจุบัน (Address)** | `TextField` (ไม่มีลิมิต DB) | สูงสุด 1,000 ตัวอักษร | Frontend Textarea Limit |
| **ชื่อแพ็กเกจทัวร์ (Tour Title)** | `max_length=255` | 5 - 255 ตัวอักษร | Real-time counter & Serializer error |
| **รายละเอียดแพ็กเกจ (Tour Desc)** | `TextField` (ไม่มีลิมิต DB) | 20 - 5,000 ตัวอักษร | Frontend Textarea |
| **หัวข้อบทความ (Blog Title)** | `max_length=255` | 5 - 255 ตัวอักษร | **[ทำแล้ว]** หน้าบ้านบล็อกการส่ง + หลังบ้านแจ้งเตือน |
| **เนื้อหาบทความ (Blog Content)** | `TextField` (ไม่มีลิมิต DB) | 10 - 50,000 ตัวอักษร | **[ทำแล้ว]** หน้าบ้านแสดงตัวนับ + ดักจับหลังบ้าน |

### 🖼️ 9. การรองรับไฟล์ภาพแบบ WebP เพื่อเพิ่มประสิทธิภาพเว็บ (Premium WebP Support)

เพื่อประสิทธิภาพความเร็วสูงสุดในการโหลดหน้าเว็บ (SEO & PageSpeed) ระบบรองรับฟอร์แมตรูปภาพ **WebP** เต็มรูปแบบทั่วทั้งระบบ (ทั้งการอัพโหลดสลิปเงินโอน, ภาพประจำตัวผู้ใช้, ภาพประกอบทัวร์, และหน้าบล็อกข่าวสาร) ดังนี้:

1. **ระดับหน้าบ้าน (Next.js Frontend):**
   * ช่องเลือกไฟล์ทั้งหมดเปิดให้แสดงผลและยอมรับไฟล์สกุล `.webp` ควบคู่กับ `.jpg`, `.jpeg`, และ `.png` ทันทีด้วยแอตทริบิวต์ `accept="image/jpeg,image/png,image/webp"`
2. **ระดับหลังบ้าน (Django Backend):**
   * โมดูล **Pillow** มีการลงทะเบียนคอมไพเลอร์ภาพและตรวจสอบความถูกต้องของ `.webp` อย่างสมบูรณ์ ทำให้ภาพทุกภาพที่ผู้ใช้อัปโหลด ถูกเก็บรักษาประเภทรูปภาพต้นฉบับไว้และแสดงผลอย่างรวดเร็วผ่าน URL ในระดับ Production
